Blueprint revision

Design-first. Firestore-first. Logic preserved.

This note records the corrections now applied across Volumes I–VI.

01 · Removed

Obsolete implementation directions are gone.

  • All references to completing, promoting, routing or rebuilding a parallel booking implementation.
  • All backend-transition phases inside the six-volume design programme.
  • All provider-neutral repository and database-cutover work from Volume VI.
  • All completion criteria that required Supabase before the design programme could finish.
02 · Locked

The current operating architecture remains untouched.

  • Firebase authentication remains active.
  • Firestore remains the current database and source used by the application.
  • Current routes, handlers, calculations, permissions and data contracts remain.
  • The current live customer and merchant components are the only redesign targets.
03 · Priority

Volumes I–VI now focus on the full product experience.

  • Design system and visual hierarchy.
  • UI and UX of every current screen.
  • Responsive layout and mobile composition.
  • Navigation, page structure and component structure.
  • Loading, empty, error, saving, success and accessibility states.
  • Presentational decomposition without moving business logic.
04 · Future boundary

Backend migration happens last and separately.

After the full design retrofit is stable and verified, create a separate programme to move Firestore data to Supabase and later remove Firebase. That work is not a prerequisite, phase or acceptance condition of these revised Volumes I–VI.
